IT Infrastructure & Emerging Technologies

IT infrastructure is the shared set of physical and software resources that every application in an organisation depends on, but that no single application owns. Because it is shared, when it fails it fails for everyone at once — which is why infrastructure decisions are management decisions, not just technical ones.

The Seven Components — Your Assessment Checklist

1. Computer hardware platformsWhat machines do we run on, and how old are they?
2. Operating system platformsWhich OS versions, and are they still supported?
3. Enterprise software applicationsWhat are the big systems of record?
4. Data management & storageWhere does the data live, and who backs it up?
5. Networking & telecommunicationsHow do pieces reach each other and the outside world?
6. Internet platformsWhat is our public presence, and where is it hosted?
7. Consulting & system integration servicesWho has the knowledge to make these pieces work together? Knowledge is a shared resource too — this is a management view of infrastructure, and it includes the humans who keep it alive.

The Responsibility Split

In every single service model — including SaaS — the data is yours. You can rent the machines. You cannot rent away responsibility for the data.

Foundations of Business Intelligence

A database is a collection of data organised so it can be stored, retrieved, and updated by many users at once, under rules the storage system itself enforces. A spreadsheet stores what you typed. A database stores only what is allowed.

The Five Diseases of the File Environment

  • Data redundancy — the same fact stored in more than one place.
  • Data inconsistency — those copies disagree.
  • Program-data dependence — changing the format breaks the programs.
  • Lack of flexibility — any new question needs new programming.
  • Poor security & sharing — no single place to enforce who sees what.

The Relational Model, Four Ideas

  1. Table — rows describing one kind of thing.
  2. Primary key — uniquely identifies every row, never empty.
  3. Foreign key — a column referencing another table's primary key; enforces referential integrity.
  4. Normalisation — every fact stored in exactly one place. If you must change something in two places to keep it true, the design is wrong.

Case: Ashworth Residence — "The Wi-Fi Dies at 8pm"

      
500 Mbps fibre, 310 Mbps peak usage (not saturated). Wired laptop: 470 Mbps. Wi-Fi laptop: 6 Mbps. All 6 access points on channel 6, 38–51 devices each, 34% retransmission rate.

      
Finding: the internet connection is at 62% capacity and is not the constraint. The constraint is wireless airtime contention from co-channel interference. Fix: re-plan to 1-6-11 (zero cost), enable band steering (zero cost), add access points (~CAD 2,400) — before buying more bandwidth.

    

  







  

    
Securing Information Systems

    
Security is a management discipline for deciding how much loss you accept, and spending accordingly — not a product. Everything protects the CIA triad: Confidentiality, Integrity, Availability. These three trade against each other; there is no configuration that maximises all three.


    

      

        
Risk Vocabulary

        

          
AssetSomething with value you're protecting

          
ThreatSomething that could cause harm

          
VulnerabilityA weakness a threat could use

          
RiskLikelihood × impact

          
ControlSomething that reduces the risk

        

        
A threat exploits a vulnerability to damage an asset; a control reduces likelihood or impact. You cannot remove threats — only vulnerabilities and add controls.
